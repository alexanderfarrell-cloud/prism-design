# Prototype Iteration and Flow Documentation

> Best practices for continuing work on the Add Employee prototype and keeping documentation in sync.

---

## Coming Back to Iterate

**1. Start a new chat with context**

- Reference the prototype: `@prototype/add-employee-prototype.html`
- Reference the PRD: `@docs/documentation/Employee_PRD_Feb23.md`
- Briefly describe the project: "Lista Payroll Add Employee prototype" or "Add Employee wizard for Lista"

**2. Be specific about what you want**

- "Update Step 3 to…"
- "Add a new step for…"
- "Change the invite flow so that…"

**3. Use research docs when relevant**

- `@docs/supporting/research/Employee-Role-Trade-Definitions.md` for decisions about role, trade, etc.

---

## PROTOTYPE_FLOWS.md

**It does not auto-update.** It's a separate document that must be updated manually when the prototype changes.

**Ways to keep it in sync:**

1. **Ask explicitly** — e.g. "Update the prototype and also update PROTOTYPE_FLOWS.md."
2. **Include it in the task** — When requesting prototype changes, ask to update PROTOTYPE_FLOWS.md in the same response.
3. **Add a project rule** — A Cursor rule or project note that says: "When changing the Add Employee prototype, also update `prototype/PROTOTYPE_FLOWS.md`."
