## Pressure-test instead of list review

**Use when:** You want to validate whether something is actually ready to use, not just whether it looks complete on paper.

> Good. Let me now do a genuine pressure-test rather than a list review. The right question is: if you tried to run the very first payroll with only what's in ADO today, what would actually fail?

**Why it works:** Shifts from checklist-style review ("is everything there?") to scenario-based validation ("what breaks when you actually use it?"). Can be adapted for other contexts by swapping the scenario (e.g., "first payroll", "first employee add", "first report run") and the source ("ADO", "the prototype", "the docs").
